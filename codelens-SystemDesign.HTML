CodeLens RAG · System Design Document

CodeLens
RAG Platform

An AI-powered codebase exploration and Q&A platform. Users paste any GitHub URL, PDF link, or Google Drive document — CodeLens ingests and indexes the entire codebase using AST-aware chunking, then powers a real-time RAG chat where users can click any line of code to ask questions about it, get error explanations, and learn how the system works — all with voice STT/TTS support.

Frontend: Next.js 14 + shadcn/ui
Backend: Python 3.12 + FastAPI
Infra: GCP + Cloudflare + GitLab CI
Auth: Supabase + JWT
AI: Groq Llama 3 + ChromaDB

05 Low-Level Design — API Contracts

Every FastAPI endpoint and its contract. Use this as your Postman collection reference. All protected endpoints require an Authorization: Bearer <jwt> header.

Ingestion endpoints
POST
/ingest
Body: {url, type: "github"|"pdf"|"gdrive"}. Clones repo or fetches file, chunks it with tree-sitter, embeds and stores in ChromaDB. Returns {task_id} for polling.
GET
/ingest/status/{task_id}
Returns {status: "pending"|"done"|"error", progress: 0-100, files_processed: n}
DEL
/ingest/{repo_id}
Deletes all embeddings and cached files for a repo. Frees ChromaDB storage.
File explorer endpoints
GET
/tree?repo_id={id}
Returns nested JSON tree of all files in the repo. Used by FileTree component to render the sidebar. Cached in Redis for 1 hour.
GET
/file?path={path}&repo_id={id}
Returns {content, language, lines[]} for a specific file. Monaco Editor renders this. Language auto-detected from file extension.
Chat endpoint (WebSocket)
WS
/chat
Client sends: {query, file, context_line: {file, line, content}}. Server streams: {token: "word"} repeatedly, then {done: true, highlight_line: N}. highlight_line tells Monaco to jump to the relevant line.
Auth endpoints
POST
/auth/verify
Verifies Supabase JWT. Used as a FastAPI dependency — all protected routes call this. Returns {user_id, email}.
GET
/health
Public. Returns {status: "ok", version, uptime}. Used by GCP health checks and Prometheus scrape.
ChromaDB data model
DOC
Collection: "codebase_{repo_id}"
id: "{filepath}:{start_line}-{end_line}" | document: raw chunk text | embedding: Jina 768-dim vector | metadata: {file, language, type: "function"|"class"|"module", start_line, end_line}
Supabase schema
TBL
Table: repos
id UUID · user_id FK · url TEXT · status TEXT · file_count INT · created_at TIMESTAMP · chroma_collection TEXT
TBL
Table: chat_history
id UUID · user_id FK · repo_id FK · role TEXT · content TEXT · context_line JSONB · created_at TIMESTAMP

# FastAPI chat handler (simplified)
@app.websocket("/chat")
async def chat_ws(ws: WebSocket, user=Depends(verify_jwt)):
    await ws.accept()
    payload = await ws.receive_json()

    query_vec = embedder.embed([payload["query"]])[0]
    raw_docs  = chroma.query(query_embeddings=[query_vec], n_results=8)
    reranked  = flashrank.rerank(payload["query"], raw_docs, top_k=5)

    # Inject clicked line as mandatory context
    ctx = payload.get("context_line")
    prompt = build_prompt(reranked, ctx, payload["query"])

    async for token in groq.stream(prompt):
        await ws.send_json({"token": token})

    await ws.send_json({"done": True})

08 Security Architecture

Every security layer applied. Defense in depth — multiple independent layers so no single failure exposes the system.

JWT Authentication
Supabase issues JWTs on login. FastAPI verifies every protected request using python-jose with the Supabase JWT secret. Tokens expire in 1 hour. Refresh tokens stored in httpOnly cookies — never in localStorage. Every WebSocket connection validates the JWT on first connect.
Redis Rate Limiting
Sliding window algorithm via Upstash Redis. Limits: 10 chat requests/minute per user, 3 ingestion requests/hour per user. Prevents LLM API cost abuse. If limit exceeded, FastAPI returns HTTP 429 with Retry-After header. Implemented as a FastAPI middleware dependency.
HTTPS + SSL/TLS
Cloudflare provisions and auto-renews SSL certificates for your domain. Cloudflare → GCP traffic uses Cloudflare's Origin Certificate (Full Strict mode). GCP Cloud Run has built-in HTTPS. All HTTP requests redirected to HTTPS via Cloudflare Page Rules. HSTS header enforced.
DDoS + WAF (Cloudflare)
Cloudflare free plan includes unmetered DDoS mitigation at layers 3, 4, and 7. WAF blocks OWASP Top 10 attacks (SQL injection, XSS, CSRF). Bot Fight Mode blocks automated scrapers. Rate limiting at the edge before requests reach GCP — protects against volumetric attacks with no cost impact.
Input Sanitization
All user-supplied URLs validated against an allowlist (github.com, gitlab.com, google drive domains only). File paths sanitised to prevent directory traversal — Path.resolve() checked against repo root. LLM prompt injection mitigated by system prompt design and user input escaping before injection into RAG context.
Supabase Row Level Security
RLS policies on the repos and chat_history tables ensure users can only read/write their own data. Policy: auth.uid() = user_id. This means even if the FastAPI backend is compromised, the database layer still enforces data isolation per user. Enabled at the Supabase dashboard level.
Environment Secrets
All secrets (GROQ_API_KEY, SUPABASE_JWT_SECRET, etc.) stored in GCP Secret Manager — never in code or Docker images. CI/CD pipeline pulls secrets at deploy time. .env files in .gitignore. Frontend env vars prefixed with NEXT_PUBLIC_ only for non-sensitive config (API URL).
CORS Policy
FastAPI CORS middleware configured to allow only your Vercel domain and localhost for development. Credentials: true, but origins are explicitly whitelisted — never wildcard (*) in production. WebSocket connections validated by checking Origin header against the same allowlist.

14 Docker & Kubernetes

Containerisation and orchestration strategy — currently in planning. Moves CodeLens from single-instance Cloud Run to a scalable, self-healing, multi-replica deployment on Kubernetes. This section is a living blueprint for the upcoming infra work.

🚧 Status: Not yet implemented. Section 07 describes the current Cloud Run + Docker Compose setup. The plan below is what replaces it once ingestion traffic and LLM cost control requires horizontal autoscaling and workload isolation.

Why Docker + Kubernetes for CodeLens

# Motivation
Reproducibility   → identical runtime locally, in CI, and in prod (Python 3.12, system libs, tree-sitter grammars)
Isolation         → RAG ingestion workers separated from chat API — a runaway clone job cannot starve chat requests
Horizontal scale  → HPA scales chat pods on CPU + custom metric (WebSocket connections) independently from ingestion
Self-healing      → liveness/readiness probes restart hung ChromaDB clients and stuck Groq streaming calls
Zero-downtime     → rolling deploys with maxSurge=1, maxUnavailable=0 keep chat sessions alive across releases
Cost control      → spot/preemptible node pool for ingestion jobs, on-demand pool for chat API

Image Security
Distroless-style runtime stage, non-root user, read-only root FS, all capabilities dropped. Images scanned with Trivy in CI — build fails on HIGH/CRITICAL CVEs. Signed with cosign, verified by Kyverno admission policy in-cluster.
Node Pools
Two GKE Autopilot workload classes: on-demand for chat API (latency-sensitive) and Spot for ingestion Jobs (cost-sensitive, interruption-tolerant via idempotent chunking + resume tokens). Spot saves ~70% on batch ingestion cost.
Persistent Storage
ChromaDB StatefulSet backed by a 50Gi pd-ssd PVC, daily VolumeSnapshot for point-in-time restore. Redis PVC 5Gi pd-balanced with AOF persistence. Both snapshots retained 7 days in GCS.
Workload Identity
Each Deployment binds a KSA to a GSA via GKE Workload Identity — no static service account keys anywhere. API pods can read Secret Manager; ingestion pods can write to GCS; no cross-privilege.
Observability
Prometheus Operator scrapes /metrics from every pod. Grafana dashboards for chat latency, WebSocket count, Groq token spend, ingestion throughput. Loki for logs with the same structured JSON schema from §06.
GitOps Delivery
ArgoCD watches the infra repo's /deploy/overlays/prod kustomize overlay. GitLab CI only builds + pushes images and bumps the image tag in git — ArgoCD syncs the cluster. Rollback = git revert.
